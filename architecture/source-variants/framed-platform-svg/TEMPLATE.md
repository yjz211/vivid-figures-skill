# VA-003 · 双侧输入输出包围的多机制平台

窄输入列和输出列夹住主平台，平台内三块分别用关系图、并列评估器和搜索树解释不同机制。外框强调系统完整性，内部异构画法承担信息密度，不能把全部模块统一成只有标题的空框。

![资产预览](preview.png)

## 适用范围

- 输入条件经多种互补机制产生多类输出的平台
- 需要将整体系统和少量内部细节放在一张宽图

不适合：三个模块实际只是同质串行步骤；没有搜索过程却想保留树形装饰。

## 阅读顺序

1. 先看左边对象和条件两组输入。
2. 中央依次读关系变换、多方法评估和候选探索。
3. 右边核对指标、时序和候选三类输出。

## 图形表达

**布局**：两侧窄列围绕三块等宽模块，主平台用独立边界包围，标题置于模块下方。

**对象**：文档、节点图、时间条、引擎列与树形对象各自编码不同产物。

**连线**：两侧短箭头仅连平台；模块相邻不等于已声明直接数据流，若需要应显式补边。

**配色**：灰条为标题和融合结构；蓝、桃、绿区分评估器，粉色突出变换或约束。

**文字**：短粗标题加内部较小标签；竖排融合标签空间有限，长词宜改横向布局。

| 对象文档 (`input-object-0`) | 列出对象结构与参数。 | 编辑文档条目或替换内部 SVG 部件。 |
| 条件输入框 (`input-1`) | 描述设备与约束。 | 与对象输入分开。 |
| 条件文档 (`input-object-1`) | 列出配置条件。 | 逐项改为真实约束。 |
| 平台边界 (`platform`) | 包含三个不同内部机制。 | 变更模块数须改布局。 |
| 变换模块 (`module-0`) | 对象转成中间结构与执行表示。 | 改对应 SVG 标签与内部对象。 |
| 图变换区域 (`module-0-graph`) | 承载节点关系。 | 改背景及图对象。 |
| 节点关系图 (`module-0-graph-object`) | 具体拓扑及类别。 | 编辑节点与连接路径。 |
| 中间产物 (`module-0-artifact`) | 显示变换后的时间或序列结构。 | 按真实输出替换内部 SVG 部件。 |
| 多方法评估模块 (`module-1`) | 并列方法进入融合。 | 编辑评估器组与结果处理。 |
| 第一评估器 (`engine-0`) | 第一类估计依据。 | 换方法名与角色色。 |
| 第二评估器 (`engine-1`) | 第二类估计依据。 | 不要只换同义标签。 |
| 第三评估器 (`engine-2`) | 第三类估计依据。 | 缺此方法时调整引擎区几何。 |
| 融合接口 (`fusion`) | 接收多个估计。 | 说明融合含义。 |
| 后处理 (`postprocess`) | 处理融合后的额外关系。 | 换为实际后处理。 |

| 规则框 (`search-rule`) | 约束候选保留条件。 | 替换真实筛选规则。 |
| 指标输出框 (`output-0`) | 汇总数值类产物。 | 改标题与内文。 |
| 指标文档 (`output-object-0`) | 列出输出指标。 | 写指标名和单位。 |
| 时序输出框 (`output-1`) | 展示安排类产物。 | 无时序输出时改类型。 |
| 时间条对象 (`output-object-1`) | 任务先后与持续时间。 | 示意条不能当计算结果。 |
| 方案输出框 (`output-2`) | 展示候选选择。 | 明确方案是什么。 |
| 方案槽位 (`output-object-2`) | 并列显示候选项。 | 换真实类别及数量。 |

## 改造步骤

1. 先确定各模块机制是否真实存在，再选择并重组相应 SVG 部件。
2. 内部图与产物必须随任务改造，不能只替换外层标题。
3. 输出类型改变时更换 SVG 内部部件和内容；两侧项目过多须扩展画布。

## 新情景示例（假设）

假设展示交通应急方案评估平台。

输入为路网与封路条件，第一模块生成可行路网，第二模块融合仿真与解析评估，第三模块探索调度方案。

重新配置路网节点、连接和方案树；时序条改成车辆任务安排，删去不存在的评估器。

## 编辑入口（SVG 资产版本）

`diagram.svg` 保存原图的全部原生图形、文字和嵌套组。`labels.json` 索引稳定文本 key、原字体和字号；`geometry.json` 记录几何，`asset.json` 登记语义部件。

`make_figure.py` 使用标准 `source_asset.run`，提供 `customize(root, context)`。使用 `context['elements']` 访问原对象、`context['parts']` 访问语义部件；也可直接编辑 SVG 的组、路径及文字。默认不修改任何对象。

### 字体与字号

源图为系统 Arial（sans-serif 回退），普通正文18、主要标题19或20 viewBox单位，并保留粗体层级；画布1100×430。print_width=468pt 时18单位为7.66pt。这是源图基线，应用场景应按最终展示宽度检查可读性，避免因扩画布无意缩小文字。

替换文字时显式指定 `font_family: Arial`，并保留原对象字号、字重；通用 runtime 未指定字体时可能采用 Arimo 回退。SVG 不内嵌 Arial，渲染设备需安装该字体。

```json
{"labels":{"e0002":{"text":"New input title","font_family":"Arial"}}}
```

### 配置与结构调整

- `labels` 按 key 修改文字，可指定 font_size/font_weight/font_style。
- `components` 按部件 id 移动、隐藏或批量设置属性；嵌套部件不要重复平移。
- `elements` 设置原对象属性；`customize()` 可重组、复制或移除原组并同步修改连线。
- 新对象应有唯一 data-asset-key，并登记到所属部件的 element_keys。跨部件连线单独维护。

三块模块为原图示例，SVG 不限制模块数量。按任务组织关系图、评估器、搜索树、输入输出等部件；保留适合当前内容的视觉语言与字号层级。

准备独立工作副本：

```text
python "<SKILL>/scripts/prepare_architecture.py" --id VA-003 --out figures/architecture
```

在工作副本运行：

```text
python make_figure.py --config example.json --out . --parts
python render_architecture.py fig.svg
```

## 本图检查

- 三模块名称是否对应实际内部对象而非抽象口号。
- 融合侧栏是否被长文字挤出引擎区域。

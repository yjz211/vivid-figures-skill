# VA-004 · 多主体反馈与共享资源调度

三列自治主体分别接收任务，在内部完成观测与策略选择，再经同一准入环节操作共享资源。成对的向下动作和向上反馈让局部决策与全局执行形成闭环，适合强调分散决策、集中约束的系统。

![资产预览](preview.png)

## 适用范围

- 三个代表性主体共享受限资源的控制系统
- 需要同时说明观测、决策、准入和资源管理的方案

不适合：只有单向任务流水线的流程；要求任意主体数自动排版的图。

## 阅读顺序

1. 先看三列任务入口与黄色主体边界。
2. 沿内部箭头从观测块读到深色策略块。
3. 对照动作下行和反馈上行，定位共享准入横条。
4. 最后看底部管理者、逻辑资源池及两组叠片。

## 图形表达

**布局**：上部等宽三列，下部通栏基础设施；窄准入条对齐各列回路。

**对象**：矩形嵌套表示所属，叠片表示成组资源；省略号说明重复模式。

**连线**：外侧回路有意倾斜，内部观测线竖直；不要把反馈线接成单向链。

**配色**：浅黄分主体、浅绿包决策区、紫色区分观测与策略；粉色只标共享准入。

**文字**：Arial 无衬线；策略白字需保持深底对比，资源标签比主体名更小。

## 改造步骤

1. 先确定三个主体与两个资源组是否能真实代表新系统。
2. 同步改动作、反馈、资源分配三类标签，使方向与含义一致。
3. 若使用规则控制，改对应 SVG 标签中的 RL Agent 标题。
4. 主体增减须同时改坐标、箭头路径和省略号位置。

## 新情景示例（假设）

假设绘制三园区充电调度。

三列对应园区，观测为排队与负荷，策略为充电配额；共享准入执行电网容量限制。

两组资源改成快充和慢充端口记录；反馈改成服务率，避免继续写奖励。

## 编辑入口（SVG 资产版本）

`diagram.svg` 保存原图的全部原生矩形、路径、文本和嵌套组。`labels.json` 是文本 key 与原字体、字号的索引，`geometry.json` 保存原始几何，`asset.json` 登记语义部件。

`make_figure.py` 使用标准 `source_asset.run`，并提供 `customize(root, context)` 编辑入口。`context['elements']` 按 key 访问原对象；`context['parts']` 提供语义部件及成员；也可直接编辑原 SVG 的组、路径和文字。默认不改动任何对象。

### 字体与字号

原图使用系统 Arial、正常字重，主文字为 21 viewBox 单位；画布为 780×678，print_width=468pt 时主文字为 12.6pt。保留原有字体、字号层级及深底白字对比。替换标签时显式指定 Arial：

```json
{"labels":{"e0003":{"text":"Replacement label","font_family":"Arial"}}}
```

通用 vector runtime 为 PDF 子集字体提供 Arimo 回退，因此不写 font_family 的替换会使用 Arimo；本资产的源字体是完整系统 Arial，使用上述选项即可保留。SVG 不内嵌 Arial，渲染环境必须安装 Arial。版面或字重改变后检查导出的 PDF 字体与实际显示。

### 配置和结构调整

- `labels` 替换指定 key 的文字；可提供 font_size/font_weight/font_style。
- `components` 按部件 id 平移、隐藏或批量设置属性。
- `elements` 按 key 设置原 SVG 对象属性。
- `customize()` 可重组、复制、移动原组并编辑连线；新增对象应设置 data-asset-key 并登记到相应部件的 element_keys。

基线为三列主体、两个资源组；这不是 runtime 的数量硬限制。改变数量时需同时修改坐标、连接、省略号和部件信息，不会自动排版。原有几何、配色与构图是复用起点；按新关系进行结构修改，勿清空原树另画通用矩形图。

准备独立工作副本：

```text
python "<SKILL>/scripts/prepare_architecture.py" --id VA-004 --out figures/architecture
```

在工作副本运行：

```text
python make_figure.py --config example.json --out . --parts
python render_architecture.py fig.svg
```

## 本图检查

- 三列上下行箭头是否各自接到同一主体，且不穿过标签。
- 准入与资源池的双向关系是否确实存在。
- 资源叠片的有意重叠是否仍保留完整前层标签。

部件图用于复用局部对象；跨边界的连接和共享容器仍需按新关系处理。示例名称、数值和曲线不是当前研究结果。

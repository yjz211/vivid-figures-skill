# 架构图：A/B 双候选

新建 SVG 架构图默认采用 **生成 A/B → 用户选择 → 交付 PPTX + SVG + PDF** 的流程。A 保留构图，B 重组构图；两张使用同一场景、主资产、图内语言和展示宽度，各自独立生成、审图和修正。先把完成的预览给用户选择，不要求用户提前选路径或逐轮指导改图。196 套资产均通过 SVG 工作副本适配，历史 Python 生成器只用于旧工程兼容。

用户明确只要一个候选、指定某条路径时按其要求执行。修改已有作品、用户已选中的候选、单纯换色/改字/格式导出时，从当前版本继续，不重新启动双候选。数据图、完整组合模板、Draw.io/TikZ 不采用本流程。

## 共同选型与任务简报

先按对象、依赖方向、共享资源、层级和反馈关系检索，实际查看候选预览与 `TEMPLATE.md`，共同确定一个适合场景的主资产。检索入口为 [交互图库](index.html) / [catalog.json](catalog.json)：

```text
python "<SKILL>/scripts/search_architecture.py" "当前任务的结构关系" --limit 8
python "<SKILL>/scripts/prepare_architecture.py" --list
```

资产是字体层次、线宽、局部造型和语义配色的共同基准。逐图说明的适用范围帮助选型；原场景中的对象和连接不能代替当前事实。没有合适资产时先重新选型或说明所需补充，不能强套。

在本图工作目录保存一份简短的 `brief.md`：用户原始需求、必须保留的对象/关系/条件、主资产 ID 与位置、语言、已知数据和禁止虚构项、共同展示宽度及用户指定的配色/交付要求。没有指定宽度时，记录同宽比较用的宽度；这不是代用户确定论文版心。简报不预先指定坐标、列数或某一路的解法，也不包含此前实验的排名和成图。

为本次图件使用独立目录，例如：

```text
figures/<图名>/
  brief.md
  original.png
  A/                 # A 独立源码、图件与部件
  B/                 # B 独立源码、图件与部件
  comparison.html
```

`original.png` 从共同选定资产的实际预览复制。A/B 分别用准备工具取得工作副本，禁止让两路写同一份源码或把 A 的成图作为 B 的起点。已有目录含用户结果时另建本次目录，不覆盖旧作品。

## 分别生成

有独立子代理能力时，并行分配两项任务，使用新上下文；模型与推理强度沿用用户当前设置，用户指定时从其要求。无需为候选创建用户侧的新聊天。

每个生成任务只接收本路径文件、共同简报、自己的输出目录，以及必要输入文件和执行环境信息。路径文件链接[共同制作与验收](COMMON.md)和实际资产；不要传入整段对话、另一条路径、对方输出或评价。

| 任务 | 读取的路径 | 核心区别 |
|---|---|---|
| A | [paths/A.md](paths/A.md) | 保留主体布局、阅读路径与有用区域比例，按需要适配局部 |
| B | [paths/B.md](paths/B.md) | 保留真实部件与设计风格，允许重排分区、方向与整体比例 |

可用如下分配文字，替换实际路径后交给生成任务：

> 按 `<SKILL>/architecture/paths/A.md` 完成 `<本图目录>/brief.md` 的图件，所有输出写入 `<本图目录>/A/`。读取路径引用的共同要求和实际资产，自主生成、看图与修正，交付完成稿及可复现源码。

B 任务仅替换路径字母和输出目录。两路不需要互相差异化，资产原构图已适合时可以相近。B 不强制先生成两套内部候选。

无法并行时依次完成两路，尽可能使用独立上下文；无子代理时按两份路径分别执行，避免参考先完成的那张，并如实说明隔离限制。宿主若不能保存或交付两个独立结果，明确说明能力限制，不能默默只交一张或声称完成双候选。当前网页工作台的单画布边界见 [AGENT.md](AGENT.md)；本文件不代表其已具备独立双候选调度。

## 自主验收与候选展示

每路都按 [COMMON.md](COMMON.md) 生成并实际查看图件，独立核对语义、同宽文字尺度、字体角色、连接、部件与可复现入口。发现实质问题就自行修正、重新查看，**不设固定的一轮或两轮上限**；检查通过或剩余问题确由缺失输入/环境阻止时停止。协调任务发现客观遗漏时，交回对应路径修复，不把另一候选的成图灌入该路径。无需用户逐轮指出排版问题。

两路各准备 `fig.png`、可编辑 `fig.svg`、矢量 `fig.pdf`、实际使用的生成代码及依赖/配置、`structure.json`、`parts/index.json` 和真实部件 SVG，供候选检查和后续导出；在简短的 `README.md` 写明实际复现命令、所用路径与未解决问题。不能只登记部件名称或生成空文件来满足交付。尚有实质问题的候选标为未完成，不能与合格稿一同声称验收通过。

两张都完成后，构建原图+A+B等宽对照：

```text
python "<SKILL>/scripts/compare_architecture_candidates.py" --original "<本图目录>/original.png" --a "<本图目录>/A" --b "<本图目录>/B" --out "<本图目录>/comparison.html" --title "当前图件的两个候选"
```

该工具只检查展示所需文件并构建页面，不替代语义、视觉和部件验收。按 A、B 顺序展示两张 PNG 和对照页，分别标为“保留构图”“重组构图”，简述取舍，并用宿主选择控件或一句简短问题让用户选择 A 或 B。此时等待选择，不代替用户选优，也不把两套 PPT 预先导出。候选源文件留在工作目录，用户可按需查看。

## 用户选定后直接交付

用户选择 A/B 或明确指出对应图后，沿该候选的当前版本完成最终导出。若同时提出修改，先只修改所选图，再导出。用户已指定单候选或当前版本时无需额外再问选择；要求两张都要时分别导出两套。

选择本身即启动最终交付，**不再询问是否生成 PPT 或需要哪些格式**。读取 [原生可编辑 PPTX](PPTX.md)，将所选 SVG 转成可编辑形状、文本框和具名组；不能用一张图片或整图 SVG 置入幻灯片冒充原生可编辑。

在新的交付目录保留同一版本的 `fig.pptx`、`fig.svg`、`fig.pdf`，并附需要的字体包。用简短的 `selection.md` 记录用户选中的路径和来源版本，避免把另一候选或旧版文件交出去。已有手改文件不覆盖。导出兼容修复若影响所选 SVG，同步刷新 PNG/PDF 并复查；无需重做另一候选。

检查 PPT 内确有可编辑文字和矢量对象、SVG/PDF 与所选稿一致，环境支持时再做 PowerPoint 保存重开及实际渲染验证。完成后直接给用户 **PPTX、SVG、PDF** 三个下载链接，字体包作为附件；无需再次征求交付确认。转换受真实格式/环境限制时先自行处理可解决的问题，保留现有文件并明确说明未完成项，不以栅格化替代或伪称 PPT 已可编辑。

# 架构图 Agent

完整 Vivid 本地服务的 `/architecture-agent.html` 用自然语言生成与修改架构图。数据图的 `/agent.html` 继续接收数据表；两者共享模型配置、连接测试、Codex CLI / 兼容 API 接口、任务进度、停止、澄清与故障恢复，工作区分开保存。

**A/B 宿主边界：** 文件型 Skill 的新图默认流程见 [A/B 双候选](WORKFLOW.md)。当前网页 Agent 使用单个项目/画布，每次最终保存一个候选，且没有独立子代理调用；尚未实现完整 A/B 调度与成对交付。能保存多份文件但仅缺并发的宿主可依次完成两路；当前网页单候选流程不能静默当作已完成默认 A/B。以下自动检查的两轮上限属于网页运行时，不是文件型 Skill 的自主修正上限。

## 使用

1. 按 [模块编辑器](EDITOR.md) 安装并启动完整 Agent 服务。从架构图库点击“交给架构图 Agent”，或直接打开架构 Agent 页面。
2. 创建工作区，描述对象、层次、连接、反馈及语言。可指定一个主体资产编号，也可让模型比较候选。沿用“一个主体，按需补充局部”的选择规则，不能以配色代替结构匹配。
3. 选择新建或修改当前图。新建保留现有图；修改先保存网页当前编辑，以此作为模型起点。选中的模块/图元会进入对话上下文。
4. 模型读取真实 Skill 流程、候选说明与实图，从196套 SVG 资产中准备主体的完整工作副本；按需准备补充资产、查看局部部件，通过 `customize()` 或实际 SVG 修改结构、语义配色与字体。Python 编辑脚本会实际运行，随后将 SVG 和具名部件结构导入工作台。简单修字或位移仍可直接用图元接口。

矢量适配遵守 [共同制作与视觉保真](COMMON.md)：修改实际 SVG 中适用的对象，不得清空、整体隐藏或替换全部对象后另画整图；在 `customize()` 中重画也不算沿用。主体不适合时可重新准备另一个主体，旧源码副本保留；当前作品续改仍以保存版本为基准。指定顶层色板时使用实际色板与角色映射，不用近似色冒充。

工作台在导入、审查与最终保存时记录原对象编号/类型、实际可见性、局部几何与分部件保留情况；无可见原对象或原图形全部消失时退回修复。当前作品与本轮开始的保存快照比较，避免把用户已有作品强制改回历史模板。统计不是保真分数，不设固定保留比例；编号沿用不等于真实复用，也不能用空壳或少量无用图元凑数。复杂遮挡等仍须查看实图。代码构图单独核对生成器，不套用矢量编号判据。

5. 开启图片检查时，检查结构表达、模块关系、保留的图形细节、字体、配色与版面；有实质问题交回同一源码流程修复，最多两轮修复再复查。审图只评价已生成图片，文件操作或权限猜测不进入改图；偏离职责的响应重试一次，仍失败则显示检查未完成并保留记录。设计 Agent 须用实图和工具证据核实审图建议。未解决问题随结果显示，不代表自动审美验收。
6. 成图直接进入同页模块工作台，可拖动、改字、撤销、保存版本，或导出 SVG/PNG/PDF/原生可编辑 PPTX。PPTX + 字体/源码包包含当前 SVG、字体、部件说明与本次源码包。继续对话沿用当前保存版本。

## 实现与边界

架构图与数据图复用同一个模型提供器、LangGraph 任务生命周期和持久化会话接口。Codex CLI 与兼容 API 使用相同的完整 Skill 工具：读取资源、准备源码、读写/修改文件、运行 Python、预览部件和导入结果。模型连接方式不决定绘图能力。网页架构 Agent 自动加载[架构子通道](../channels/vivid-architecture-diagram-skill/SKILL.md)、[共同制作与验收](COMMON.md)和[语义配色](PALETTE.md)，不自动注入根路由、数据图规则或文件型 A/B 调度流程。`read_skill` 默认读取架构子通道，其他资料按需指定；`<SKILL>` 与工具路径仍以整个 Skill 包为根，资产和脚本位置不变。检索与命令行共用同一排序实现。

完整源码工具允许重组布局、抽取和融合其他资产的矢量部件、修改路径、使用已安装的 Python 算法库，以及完整语义配色与字体处理。模型应保留有用底稿细节，并统一补充部件的字体、尺寸、defs 引用和模块编号。结构是否正确、是否需要补充仍由任务和实际图决定，不要求每图强行拼接多个资产。

当前 Windows 源码执行器依赖本机 Codex sandbox 运行时；即使模型使用兼容 API，代码执行仍需该本地运行时。生成代码仅在任务工作目录获得写权限；无隔离执行器时明确报错，不退回直接运行。脚本环境不传递模型 API 密钥。模型不通过网页接口执行任意 shell，Python 工具可用本机已有库，不自动安装依赖。此限制是执行环境边界，不是将绘图限制成几种方框。

生成的 SVG 经校验后进入模块工作台；禁止活动脚本、外链、位图替代可编辑架构。源码、主体和补充资产、字体及来源清单随版本保留。手动修改后的当前 SVG 是后续改图起点，旧生成器仅作参考；最终导出 SVG 是该版本的实际结果。原生 PPT 仍沿用相同图元和模块归属。

网页手动编辑仍不提供路径节点编辑、模块缩放或自动布线；Agent 可通过源码重新布线。这并非把外部服务、任意工具安装、所有系统命令都开放给模型。数据图仍使用原数据表工作台和原渲染器，本轮扩展的是架构图生成入口。

每次模型修改生成独立快照；保存用版本比较，期间出现手动新版本时保留模型候选，不覆盖人工编辑。历史版本保留各自基线。停止任务不提交未完成候选。

实际模型测试使用 Codex CLI；兼容 API 共用工具适配，仍需对应服务凭据验证。早期指定 VA-147 的例子只验证了模板替换和续改，不能作为完整设计能力的证据。完整源码入口另用不指定资产/布局的需求进行测试，实际比较三套资源、读取主体与补充源码、编写运行生成器并保存可编辑结果。此例参考了布局与关系，但没有直接移植参考资产几何；不得声称已验证部件移植效果。代码工具提供复用能力，是否实际复用须查源码记录。单例仍不能证明全库自动选型质量。

安装版 Skill 的 `workbench` 是离线参考图库，不含完整服务。这里描述的 Agent 与模块编辑功能在桌面完整工作台运行；离线包不冒充可直接启动的 Agent 应用。

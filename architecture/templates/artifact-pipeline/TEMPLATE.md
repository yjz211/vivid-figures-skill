# VA-002 · 逐阶段推导与中间产物列

用输入、处理阶段、产物三列讲清方案如何形成。中列顺序推进，右列把每步抽象操作落实成图、曲线、分配表或时间表，末步回到左下执行端。它适合强调推导过程的总览，示意小图本身不构成计算证据。

![资产预览](preview.png)

## 适用范围

- 多步规划与调度方法
- 每步都有可解释中间表示的算法

不适合：并行分支占主导的流程；只有最终结果、没有阶段产物的方法。

## 阅读顺序

1. 从左栏输入确认问题对象与资源条件。
2. 沿中栏自上而下阅读阶段依赖。
3. 逐行向右核对该阶段实际生成什么。
4. 由末阶段沿左向箭头进入执行端。

## 图形表达

**布局**：三栏固定横向位置，行高随阶段数累加；输入可对齐不同阶段。

**对象**：浅绿步骤卡叠浅灰阴影；产物用虚线小框容纳具体图元。

**连线**：中列短竖箭头表示依赖，横箭头表示产出；输入折线必须接到真正消费该输入的阶段。

**配色**：主体用低饱和灰绿，产物内部颜色区分任务或资源，暖红斜体标出产物名称。

**文字**：栏标题与阶段名加粗，长阶段名可分两行；产物标题短于一整句。

## 部件与复用

| 部件 | 含义 | 改造方法 |
|---|---|---|
| 阶段总区 (`planner`) | 限定顺序推导的整体边界。 | 阶段数变化时自动延长边界，分支结构需另写代码。 |
| 首阶段 (`stage-0`) | 接收初始问题并转换表示。 | 按 stages[0] 改操作名称与产物。 |
| 第二阶段 (`stage-1`) | 对前一步表示作分析。 | 如改成预测，右侧曲线必须随之替换。 |
| 第三阶段 (`stage-2`) | 形成资源或决策分配。 | 分配格颜色应与对象身份一致。 |
| 第四阶段 (`stage-3`) | 把决策转换为执行顺序。 | 时间条若是实算值需给定实际时间。 |
| 末阶段 (`stage-4`) | 生成可执行配置。 | 执行端连线始终跟随最后一个阶段。 |
| 图结构产物 (`artifact-0`) | 展示节点及依赖关系。 | 以实际节点和边替换示意图。 |
| 曲线产物 (`artifact-1`) | 展示趋势或函数近似。 | 保留示意标识或换成真实计算曲线。 |
| 分配格产物 (`artifact-2`) | 展示对象到资源的归属。 | 明确行列以及空格的含义。 |
| 时间安排产物 (`artifact-3`) | 展示任务在时间轴上的占用。 | 重新定义起止时刻和泳道。 |
| 执行矩阵产物 (`artifact-4`) | 展示最终放置关系。 | 矩阵维度须与资源数量吻合。 |
| 问题输入 (`input-0`) | 提供初始结构。 | 用 object 字段修改具体图元。 |
| 资源输入 (`input-1`) | 提供可用资源关系。 | row 与 target 分别决定位置和接入阶段。 |
| 执行端 (`runtime`) | 接收最终计划。 | 改为实际执行者或仿真器。 |
| 产物图节点 (`artifact-glyph-0`) | 产物框内的独立依赖图。 | 修改节点和边。 |
| 趋势曲线 (`artifact-glyph-1`) | 产物框内的独立曲线对象。 | 替换 series 并保留示意说明。 |
| 分配单元格 (`artifact-glyph-2`) | 资源分配的内部格子。 | 修改 rows 和对象色彩。 |
| 时间条 (`artifact-glyph-3`) | 排程框内的独立时间对象。 | 改任务时段与泳道。 |
| 执行单元格 (`artifact-glyph-4`) | 执行矩阵的内部格子。 | 修改 cells 与行列定义。 |
| 输入依赖图 (`input-glyph-0`) | 输入框中的具体节点关系。 | 修改 object 中的 nodes 与 edges。 |
| 输入资源图 (`input-glyph-1`) | 资源框中的拓扑对象。 | 按真实连接替换节点和边。 |

## 改造步骤

1. 先列出每步输入输出，删去没有实质产物的阶段。
2. stages 增删后检查输入 row 是否挤占底部执行端。
3. 图、曲线、矩阵等 artifact.kind 要符合产物类型。

## 新情景示例（假设）

假设用于应急车辆调度。

输入为路网和车队，中列依次完成需求聚合、行程估计、车辆分配、出发排程和路线下发。

将神经计算类图元替换为路网与车辆表；右栏使用线路图、时间曲线及车次矩阵。

## 编辑入口

**入口**：make_figure.py 的 build(c) 读取 example.json；可通过 --config、--out、--parts 运行并导出部件。

**配置可改**：stages 控制阶段数、阶段名、产物标题和 artifact；inputs 控制输入标题、row、height、target 与 object；runtime 及三个栏标题可配置。

**需改代码**：改变三栏布局、增加反馈支路或更换未支持的产物图元需改 build(c) 或共享 glyph；改变阶段数量已有配置支持。

**字体**：沿用共享 Diagram 的无衬线文字设置；阶段名可显式换行，产物名使用斜体。变长后检查标签换行与缩印大小，字体并非本配方独立参数。

准备独立工作副本：

```text
python "<SKILL>/scripts/prepare_architecture.py" --id VA-002 --out figures/architecture
```

在工作副本运行：

```text
python make_figure.py --config example.json --out . --parts
python render_architecture.py fig.svg
```

## 本图检查

- 每个阶段均有与操作匹配的产物。
- 输入 target 指向实际使用资源信息的阶段。
- 最后一行与左下执行框不重叠。

部件图用于复用局部对象；跨边界的连接和共享容器仍需按新关系处理。示例名称、数值和曲线不是当前研究结果。

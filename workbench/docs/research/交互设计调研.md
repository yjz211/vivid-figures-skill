# Vivid 工作台交互设计调研

调研日期：2026-09-22。基于公开项目源码说明、官方文档、GitHub issue、KDE 社区和浏览器演示检查。此轮为设计与选型研究。

## 结论

优先组合：Tabulator 提供成熟表格操作；Origin 提供对象选择、快捷工具条和模板复用的交互参考；Pylustrator 提供“原 Python 图形＋可保存的编辑操作”思路。现有模板继续使用完整 Python 源码，前端负责数据、设置和图形对象选择。

目前多数模板在编辑器中显示 PNG；图片本身没有曲线、坐标轴等可选对象。实现点击图形改样式，需要渲染器提供对象标识与可编辑属性，不能仅靠更换按钮或图表组件完成。先支持标题、坐标轴、图例，再逐类增加系列和标注，能控制复杂度。

- [Glide Data Grid](https://github.com/glideapps/glide-data-grid)：MIT，React 表格，适合大规模可编辑数据网格；当前网页不是 React 项目，暂列备选。
- [React Data Grid](https://github.com/Comcast/react-data-grid)：原 adazzle 项目已重定向至 Comcast。GitHub API 的许可证标识为 Other，实际 LICENSE 文本为 MIT；需要读取实际许可证，不能只看徽章。
- [ipympl](https://github.com/matplotlib/ipympl)：为 Jupyter 提供 Matplotlib 交互，不适合直接作为当前独立网页的基础。
- [Matplotlib WebAgg](https://matplotlib.org/stable/gallery/user_interfaces/embedding_webagg_sgskip.html)：官方提供嵌入 Web 应用的实现范例，可用于保留 Matplotlib 原生绘图的交互路线验证；需要长驻图形会话和连接管理，不是替换 PNG 标签即可完成。

## 从社区反馈得到的验收重点

1. [react-chart-editor issue #1180](https://github.com/plotly/react-chart-editor/issues/1180) 报告：直接编辑图内标题未触发 onUpdate，侧栏设置能更新，导致保存结果不同。本次读取时 issue 仍显示 Open；这是用户报告，不等于本次复现了所有当前版本的问题。Vivid 应测试“修改、撤销、重开项目、导出图片、独立源码复现”的一致性。
2. [KDE LabPlot 社区](https://discuss.kde.org/tag/labplot/307) 有移动图形、单独调整标签等使用问题。对应设计应明确选择、拖动、平移模式，提供复位及撤销，避免一次拖动同时改变图形与视图。
3. [Pylustrator 文档](https://pylustrator.readthedocs.io/en/latest/styling.html#increasing-performance) 说明大量图形元素会使每次编辑重绘变慢，并提供栅格化显示。Vivid 可采用轻量预览、交互结束后更新、高清导出按需生成。
4. Tabulator 文档明确：区域选择依赖 Virtual renderer，双击或 Enter 编辑更适合配合区域选择；粘贴填充存在重复填满或截断到选区的行为。Vivid 接入时应明确“覆盖选区”与“扩展数据表”，保留现有容量校验和项目级撤销。

## 适合当前工作台的实施顺序

### 第一阶段：数据操作

使用 Tabulator 替代当前 contenteditable 表格，提供选区、键盘移动、批量复制清空和列宽调整。继续复用现有导入接口、数据校验、字段对应和项目格式。字段匹配可以按列名与类型自动建议，有歧义时由用户选择；排序、转置或聚合必须在用户明确操作后执行，原始数据和改变后的数据有可恢复记录。

验收：CSV/XLSX、多表切换、撤销、字段对应、中文输入法、带表头和不带表头的粘贴、容量限制、删除已绑定列，都与当前行为衔接。

### 第二阶段：图形对象与属性

参考 Origin：选中标题就显示文字设置，选中坐标轴就显示范围和刻度，选中图例就显示位置和列数。保留现有右侧面板，使用一个就近快捷工具条；复杂设置折叠。优先做标题、坐标轴和图例，通过后再扩展系列和注释。

所有操作写入项目设置；参考 Pylustrator，把这些设置转换为可复现的原生图形修改代码，继续保留完整模板绘图主体。数据维度变化导致某个对象不存在时，明确标记该项失效，避免把旧设置错误施加到另一个系列。

验收：操作能撤销；重绘、重新打开和独立源码包保持一致；改变数据数量后对象对应正确。

### 第三阶段：原生交互与项目复用

先开放现有 Plotly 模板的旋转、悬浮和缩放，并保存三维相机。对 Matplotlib 用少量代表模板验证 WebAgg 或带对象映射的矢量预览，选取能保持模板细节的方案后再扩展。增加样式预设、最近项目和本地自动保存。

验收：交互预览与最终导出使用相同视角、坐标范围和参数；所有输入和结果留在本机，基础操作无需模型。

# Vivid Agent 工作台 · 使用与架构

目标：在本地网页内完成数据导入、模板检索、真实模型驱动的出图与修改、手动编辑、版本恢复和源码导出。现有 148 个模板和 7 套配色继续使用原渲染代码。

## 启动与使用

Python 3.11+、Node.js 18+、Chrome/Chromium 和中文字体。Node.js 只用于复用原编辑器的数据整理模块；基础绘图仍由 Python 完成。

```sh
cd workbench
python -m venv .venv
# Windows；macOS/Linux 用 .venv/bin/python
.venv/Scripts/python -m pip install -r requirements-agent.txt
.venv/Scripts/python -X utf8 scripts/manage.py agent --open
```

安装后可双击 `启动Agent工作台.cmd`。默认打开选图图库 <http://127.0.0.1:8766/index.html>；先选择模板，再进入编辑。需要助手时，点击顶部「Agent 工作台」进入 <http://127.0.0.1:8766/agent.html>，同一个服务提供这三个页面。如果旧工作台已经占用 8766，先关闭旧服务，或通过 `--port 8767` 使用其他端口。

### 无需模型：选模板、对应字段、出图

1. 创建工作区，导入 CSV、TSV 或 XLSX。Excel 先读取工作表名称；多表时自行选择，再读取数据，首张封面或说明页不会阻止选择其他表。原始表保留，表格修改会另存新表。
2. 按名称、关键词或类型检索图库。可「打开示例」先看效果，也可直接「用我的数据」。
3. 在数据对应窗口选择已经导入的表，再指定标签、数值、分组、坐标或矩阵列。组合图的每一部分单独绑定；误差列按模板能力选择，未提供的误差不会自动补造。
4. 确认名称与配色，点击「生成新图」。字段校验通过后，由同一套模板源码出图；存在的问题会在数据对应窗口说明。也可点击「交给助手对应」继续对话。

### 使用助手：明确操作对象与数据

1. 默认使用本机 Codex CLI。先安装并通过 `codex login` 登录；工作台不读取登录文件。也可在「模型设置」填写兼容 API 地址、模型名称和密钥，再测试连接。
2. 对话框上方选择「新建一张图」或「修改当前图」，以及本次使用的数据表。新建会保留现有图；修改默认沿用当前图的数据。指定数据表后，助手只接收所选表及由其整理得到的新表。
3. 输入要表达的关系、比较目标或修改要求。助手可检索模板、检查字段、整理数据、渲染和检查实际图片；缺失必要信息时提出具体问题。工具进度、累计时间、停止与补充入口在对话区显示。
4. 点选画布对象后，对话上下文会显示其名称。「×」清除对象选择；切换到新建图时不沿用旧图的对象选择。

### 继续编辑与交付

数据与属性面板默认收起，点击画布工具栏中的数据、样式或对象入口展开。选择文字后，编辑条留在画布外；可修改文字、字号与颜色，直接拖动调整位置，按 Esc 或「×」取消选择。顶部配色选择会重新渲染当前图，并保留手动位置。Plotly 图使用原生三维交互。

手动修改自动保存为版本。「版本」可以查看某次渲染的实际图片、恢复为新版本或另存图表；未渲染的版本会明确标记。继续对话使用当前版本；Agent 结果若与期间的手动编辑冲突，可另存候选图。「导出」支持当前渲染器提供的 PNG、PDF、SVG、CSV、源码及完整复现包。

窗口宽度不超过 1050 像素时首次载入默认收起助手，不超过 700 像素时也收起工作区；顶部按钮可展开。切换期间旧画布暂时停止接收操作，旧请求返回不会覆盖新工作区；加载失败时保留原来的图。

模型执行需要连接所选服务，会发送当前任务所需的摘要和图片。渲染、版本和文件存储在本机。API 的 JSON 输出、图像输入兼容程度因服务而异；文字模型可以关闭图片检查。真实模型测试当前覆盖 Codex CLI，兼容 API 尚需使用者自己的服务凭据验证。

## 产品布局

- 左侧：工作区切换、数据表、图表列表。一个工作区可包含多表、多图。
- 中间：原有编辑器；优先显示画布，数据表与属性面板按需展开。模型和人操作的是同一份可编辑项目。
- 右侧：绘图对话、新建或修改目标、所选数据、选中对象、当前工具进度、停止按钮、澄清与恢复入口。模型未连接时仍能直接绑定数据并绘图。
- 图库：直接读取现有知识卡、关键词、类型与 148 个模板的粉彩少女预览。
- 版本：按图表记录，可预览当时的图；恢复创建新版本，并发修改发生冲突时保留候选图。

## 前后端结构

```text
agent.html + agent.js ──────────────── FastAPI /api/agent/*
  │ 对话、工作区、版本、AG-UI SSE         │
  └ 原 editor.html + 明确 bridge        ├ SQLite 项目、数据、版本、消息、任务与事件
       表格 / 手动拖动 / 导出              ├ LangGraph + SQLite 检查点
                                          │  规划 → 工具 → 规划 / 图片检查 → 保存
                                          │            ↘ 澄清暂停 → 补充后恢复
                                          └ Codex CLI / 兼容 API → 结构化操作
                                               ↓
                                  原数据转换、数据契约、对象编辑与 worker.py
                                               ↓
                                  完整模板源码 → 图片、对象清单、复现包
```

前端使用现有原生 JavaScript、CSS 与 Tabulator，不为增加聊天框重写编辑器。FastAPI 提供新的会话接口，兼容原 `/api/templates`、`/api/sample`、`/api/import`、`/api/render`、`/api/jobs`、`/api/library`。AG-UI 使用真实协议事件和 EventEncoder，通过 SSE 推送；事件保存在 SQLite，断线可按事件编号重放。模板和数据处理有明确工具契约；模型无权直接改仓库源码。

LangGraph 节点是 `plan`、`execute`、`clarify`、`review`、`finalize`。默认最多 8 轮规划，错误最多修复 2 次；图片检查最多做一轮局部排版修复，再复核一次。颜色、数据、文字含义和用户已设定的属性由执行流程及项目版本负责，图片检查不能擅自重做。

SQLite 的项目版本是权威状态，模型的记忆和 SSE 状态快照都不是。每次保存需提交基准版本号；不匹配时保留 Agent 候选或尚未保存的手动修改。恢复任务时，数据变换和最终图表保存使用固定操作编号，避免重放产生重复图表。单个工作区同时只运行一个任务。

## 工具与职责

| 工具 | 输入与结果 |
| --- | --- |
| search_templates / inspect_template | 关键词 → 卡片、数据契约和模板设置；先了解数据要求 |
| inspect_data | 表编号 → 列类型、缺失值、范围和少量样例 |
| transform_data | 排序、筛选、转置、长宽表转换、明确口径的分组汇总；另存新表 |
| bind_template | 模板、新建或当前图目标、真实表及列对应 → 项目；多表模板必须绑定齐全 |
| update_settings | 配色、标题、尺寸等已允许设置；未提及属性保留 |
| inspect_objects / edit_object | 实际渲染对象及允许属性；修改已有对象 |
| render | 原模板源码 → 当前项目的真实输出，失败返回明确原因 |

第一轮只发送紧凑的模板目录；后续按检索与当前图形提供上下文。数据摘要在本地计算，不把整份大 CSV 反复塞进提示。只有图片检查会发送当前图片和模板参考。每轮模型用量与耗时写入任务记录；CLI 自带上下文仍有额外消耗，因此这一版不承诺固定时延或 token 数。

## 与完整开源应用的取舍

Data Formulator、CoDA 等项目自带渲染体系、UI 和数据管线，直接整包接入需要重新处理全部模板的可编辑对象。第一版采用它们的数据线程、工具规划和检查机制，直接依赖成熟的 LangGraph、AG-UI、FastAPI；模板、数据表和画布继续使用已有实现。

## 实施顺序

1. 安装并固定 LangGraph、AG-UI、JSON Patch；核验本机 Codex CLI 登录与结构化输出。另提供通用兼容 API 配置。
2. 新增本地 SQLite 项目、数据、版本、消息与任务存储；版本比较防止覆盖并发手动修改。
3. 将已有模板、校验、数据操作、对象编辑和渲染封装为受控工具；LangGraph 管理执行、澄清、修复和恢复，AG-UI 传输可重放事件。
4. 新增像素风 Agent 工作台，通过明确接口嵌入既有编辑器；模板库、数据导入、模型设置、任务停止、历史版本与导出均可操作。
5. 执行真实模型、API、浏览器与源码复现测试，修复后启动本地版本供用户查看。

## 数据与执行边界

- 原始数据与模板只读；修改形成新版本。模型只获得所需字段摘要、有限样例与指定的预览图。
- 第一版 Agent 使用现有模板和声明式数据/对象操作。未知操作会给出明确错误，不能悄悄改用自写绘图代码或示例数据。
- 单图是可编辑项目；工作区可以保存多张图和多个数据表。每次渲染绑定准确的项目版本。
- 用户手动修改与 Agent 修改都进入版本记录；版本冲突保留候选结果，由用户选择新分支。
- 模型设置与凭据不进入 Git、浏览器存储、图表项目或源码包。未接入模型时保留手动图库与编辑器。
- 云端模型调用会发送任务所需摘要和图片；不宣称整个 AI 流程离线。

## 验收

- 真实模型执行一次选图/字段绑定/渲染和一次已有图修改。
- 所有 148 个模板可检索与选用；保留各自的数据契约。
- 数据导入、整理、手动拖动、Agent 编辑、撤销恢复、停止和错误恢复可操作。
- 历史版本与当前结果一致，旧运行不能覆盖新修改。
- 复现包再次运行能生成当前图；模板来源检查通过。
- 模型配置隐藏凭据；任务日志与导出不会泄露凭据。
- 浏览器截图、测试结果与本地启动入口可交付。

## 当前边界与后续顺序

第一版是围绕现有模板的 Agent。它能选择、绑定、整理和修改，不执行任意模型生成的 Python，不从截图发明新模板，也不替代专业统计建模软件。Plotly 使用原生三维交互，Matplotlib 的文字支持画布拖动。完整源码包仍由现有渲染器生成。

后续应先积累真实用户任务，改进选图/字段绑定的失败案例、补充更多模型兼容验证，再做有来源差异检查的源码局部修改工具。暂不引入多 Agent 编排、云端多人协作和另一套图表引擎，避免基础操作变复杂。
